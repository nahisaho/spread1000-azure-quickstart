# 07 — 倫理と限界

## LLM 抽出の限界

- **エンティティ・関係の誤抽出**: LLM は 5-15% の誤り率で誤ったエンティティ名や関係を生成する
- **ハルシネーション**: 文書に書かれていない関係を「もっともらしく」推論することがある
- **抽出漏れ**: 文書中に明示された関係でも見落とすことがある
- 検証には**サンプル抜き取り + 人手チェック**が必須

## コミュニティ検出の限界

- Leiden はハイパーパラメータ (`max_cluster_size`) に敏感
- 同じデータでも実行ごとに微妙にクラスタリング結果が変わる (乱数依存)
- コミュニティの「意味」は post-hoc の LLM 要約に依存 → **要約自体もハルシネーションの余地**

## global search の要注意点

- 全 community report を LLM に投入するため、**コンテキスト崩壊**が起こり得る
- 「〜について何が書かれている?」という質問に「〜が最も重要」と過度に断定的な回答を返す傾向
- 定量的 (%, 件数, 年代) の質問には向かない — 出典を必ず参照

## 出典表示の限界

- GraphRAG は `[Data: Entities (5, 12); Relationships (7, 9)]` 形式で出典を付ける
- しかし ID → 元文書行番号のマッピングは自明でない
- 「entity 5」が文書中のどの記述に対応するかは `entities.parquet` の `text_unit_ids` を辿る必要がある

## 対象文書の著作権

- 学術論文、書籍、ニュース記事などを未許諾で GraphRAG 化し**公開**することは著作権侵害の可能性
- 私的研究利用は日本の著作権法 30 条の 4 で認められる可能性が高いが、**成果物の外部公開**は要注意
- 公開時は原文書に**明示的な利用許諾** (CC-BY, CC0, Public Domain) があるものに限定

## 個人情報の取り扱い

- 現代人物の SNS 投稿、インタビュー記録などから人物ネットワークを構築する場合、**個人情報保護法** (日本) / **GDPR** (EU) の対象
- 匿名化してから GraphRAG に投入することを推奨
- **要配慮個人情報** (人種、信条、病歴等) は絶対に混入させない

## LLM への文書送信リスク

- Azure OpenAI は既定で**入力データを Microsoft の学習に使わない**契約 (2023 年以降のデータプライバシー方針)
- しかし内部監査・不正利用調査目的で最大 30 日間ログ保持
- 極めて機密性の高い文書 (未公開研究、個人医療記録等) は **abuse monitoring opt-out** 申請 (Microsoft 承認必要) を検討

## 費用超過のリスク

- 大規模コーパスでうっかり `gpt-4o` で index すると **$100〜$1000** に達する可能性
- **必ず** 予算アラートを設定 (`docs/06-cleanup.md` 参照)
- 試行時は 3-5 文書に絞ってコスト感覚を掴む
